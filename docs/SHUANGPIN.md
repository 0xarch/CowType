# 双拼输入

在设置的“拼音”节启用“双拼输入”，选择自然码、微软、紫光、智能 ABC、中文之星、拼音加加、小鹤或国标。该选项作用于 CowType 拼音，五笔保持独立。方案使用 libime 的公开双拼 profile 与 PinyinContext 解码器，共享拼音词库、统计模型、候选排序与学习记忆，不建立另一份词库。预编辑保留双拼原始按键，读音与学习使用全拼，部分候选的消费范围按原始双拼按键计数。

占用分号的双拼方案把分号作为编码字符；其他方案保留普通分号标点。原生 profile 决定字符序列是否可以解码。退格、光标编辑、数字选词、分页与取消使用普通会话规则。双拼输入关闭自动 `u` 前缀 Unicode 匹配，以避免声母按键被截取；独立 Unicode 模式快捷键仍可用。全拼专用的补充错拼搜索不处理双拼，双拼纠错由支持该能力的 libime profile 提供。

## 手动方案

选择“自定义”，在“自定义方案文件”填写绝对路径，按输入行的应用按钮保存。加载候选引擎期间，插件按已校验的方案能力接收分号；五笔不使用此能力。方案文件可放在 `$XDG_CONFIG_HOME/cowtype/shuangpin/`；用户自行维护多个文件，通过路径选择。保存和重新加载配置时读取方案；文件变化后保存一次设置可重新加载。文件须小于等于 64 KiB，必须包含至少一条有效映射；路径不可用、映射无效时报告加载错误，不自动选择其他方案。

格式兼容 libime 文本 profile。以下内容为 CowType 编写的最小演示方案，不能当作完整拼音方案使用：

```ini
[方案]
方案名称=我的示例方案
[零声母标识]
=o
[声母]
sh=u
[韵母]
ao=k
an=j
[音节]
ni=n;
hao=h;
an=oa
```

`[声母]`、`[韵母]` 每行把完整读音映射到一个小写字母或分号；相同读音可重复定义别名。单字母声母和韵母使用自身按键，除需覆盖别名外可省略。`[音节]` 将完整音节映射到两个按键，供零声母和特殊音节使用；同样可以重复定义别名。`[零声母标识]` 中 `=o` 表示零声母前缀，`=*` 表示使用音节自身首字母；这些规则由 libime 解读。方案名称只作说明，不影响映射；CowType 将名称从解码输入中剥离。

文件只描述读音映射，不执行程序。配置诊断不记录用户输入、个人词条或方案文件内容。

## 版本兼容与来源

最低 libime 1.1.7 提供七种内建 profile 和自定义流构造。1.1.10 增加带纠错 profile 的构造函数，1.1.15 增加国标 profile。CowType 在 `engine/shuangpin.h` 集中选择对应接口：较早版本使用原构造，国标通过相同标准映射的文本 profile 构建。较早版本的双拼纠错能力受 libime 接口限制，普通转换与方案选项保持可用。

参考实现为 fcitx5-chinese-addons 提交 `e8d930f402e359cfd76a101ee3e46815d1331d83` 的 profile 选择和复用 PinyinContext 的架构；解码 API 核查来自 libime 提交 `53df6a248793f9a00c1769e658630de313f3e419`，二者相关代码按 LGPL-2.1-or-later 分发。CowType 的适配与设置代码自行实现，没有复制 fcitx5-chinese-addons 的示例方案。国标兼容表来源、转换与许可见 [通知](../src-fcitx5/engine/SHUANGPIN-NOTICE.md)。

原生测试覆盖八种方案的固定编码、零声母、半码、分号编码、自定义音节、错误文件拒绝、通过 Rust C ABI 的会话输入和 GB 兼容表等价性。旧接口分支用同一固定样本执行；该分支检查不代替旧发行版上的真实依赖构建。
